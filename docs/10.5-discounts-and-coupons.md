# Discounts & Coupons

## 1. Objetivo

Este documento define el sistema de descuentos y cupones comerciales aplicables a suscripciones pagas.

El objetivo es soportar campañas como:

```text
20% OFF

50% OFF first month

USD 2 OFF

launch price

partner discount
```

sin confundir estos mecanismos con:

```text
Promotional Pro Access

Referral Rewards

Mercado Pago Subscription State
```

Principio central:

```text
Discount
≠
Promotional Access
≠
Referral Reward
≠
Subscription
```

---

# 2. Qué es un descuento

Un descuento modifica:

```text
the amount charged
```

por una suscripción paga.

Ejemplo:

```text
PRO_MONTHLY

Normal:
USD 7.99

Coupon:
25% OFF

Charged:
USD 5.99 approximately
```

El usuario sigue teniendo:

```text
PAID PRO
```

No acceso promocional.

---

# 3. Qué no es un descuento

No usar este sistema para:

```text
30 days free Pro

beta access

support compensation

referral Pro days
```

Esos casos pertenecen a:

```text
Promotion / Promotional Access
```

---

# 4. Commercial Model

Plan principal:

```text
PRO_MONTHLY
USD 7.99 / month
```

Un coupon puede modificar temporalmente el precio efectivo.

Ejemplo:

```text
PRO_MONTHLY
USD 7.99

WELCOME20
20% OFF first billing period
```

---

```text

```

Futuro:

```text

```

si se necesita.

Ejemplo:

```text
20%
```

```text
discount =
basePrice × 0.20
```

---

# 7. Fixed Amount Discount

Ejemplo:

```text
USD 2.00 OFF
```

Cálculo:

```text
finalPrice =
basePrice - 2.00
```

# 8. Fixed Price Future

Ejemplo:

```text

USD 3.99
```

Puede ser útil comercialmente, pero no es necesario para V1 si `PERCENTAGE` y `FIXED_AMOUNT` cubren los casos principales.

# 13. Coupon Status

Estados:

```text
DRAFT

ACTIVE

PAUSED

EXPIRED

REVOKED
```

---

# 14. DRAFT

No puede redimirse.

---

# 15. ACTIVE

Puede utilizarse si cumple todas las demás condiciones.

---

# 16. PAUSED

No acepta nuevas aplicaciones.

Los descuentos ya asociados a suscripciones existentes continúan según sus términos.

---

# 17. EXPIRED

La ventana de aplicación terminó.

---

# 18. REVOKED

No puede utilizarse nuevamente.

No significa necesariamente cancelar descuentos ya aplicados.

---

# 19. Redemption Window

Separar:

```text
when coupon may be redeemed
```

```text
how long discount applies after redemption
```

```text

```


```text

```

# 45. Minimum Final Price

No permitir:

```text

```

---

# 46. 100% Discount

Puede existir conceptualmente, pero:

```text
100% discount
```

se parece a acceso promocional y puede no funcionar correctamente con recurring billing/provider.

Recommended:

```text
do not support 100% billing coupons in V1
```

Usar Promotional Access para regalar Pro.

---

# 47. Maximum Percentage

Recommended:

```text

```

# 48. Fixed Discount Validation

Si:

```text

```

```text

```

# 67. Provider Capability Must Be Verified

```text

```

El adapter de Mercado Pago implementa lo soportado.

# 96. Why Minimum Price Matters

Normal Pro economics currently assume:

```text

~10% gateway cost

bounded AI

bounded WhatsApp
```

Large recurring discounts can destroy contribution margin.

# 221. Commercial Mechanism Separation

```text
PROMOTION CODE
→ temporary Pro access
→ no subscription required
```

```text
DISCOUNT CODE
→ reduced paid price
→ subscription required
```

```text

```

# 223. Additional Invariants

```text
Discount calculations are server-side.

Exact money is used.

Coupon usage limits are concurrency-safe.

Checkout revalidates coupon.

Provider failures do not consume abandoned coupon slots permanently.

Repeated webhooks do not duplicate redemptions.

Existing redemption terms never change when coupon config changes.

100% discounts are handled as promotions, not billing coupons, in V1.

Gateway fees remain part of discount economics.

Discount campaigns must be measurable.
```

# 224. Final Product Rule

Los cupones deben incentivar una conversión paga sin alterar el significado de una suscripción.

La regla es:

```text
NORMAL PRICE
↓
VALID COUPON
↓
DISCOUNTED PRICE
↓
PAID CHECKOUT
↓
PRO
```

Nunca:

```text
COUPON
↓
fake paid subscription
```

y nunca:

```text
COUPON
↓
unlimited commercial discount
```

sin límites claros, auditoría y análisis de unit economics.
