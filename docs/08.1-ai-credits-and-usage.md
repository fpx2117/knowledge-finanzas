# AI Credits & Usage Control

## 1. Objetivo

Este documento define cómo se controla, limita, contabiliza y comercializa el uso de inteligencia artificial dentro de la aplicación.

Complementa:

```text
docs/08-ai-openrouter.md
docs/10.1-subscription-plans-and-limits.md
docs/10.2-pricing-unit-economics.md
docs/10-billing-subscriptions-mercadopago.md
```

El modelo comercial actual es:

```text
TRIAL
+
PRO
+
EXPIRED_READ_ONLY
```

Por lo tanto:

```text
AI Usage
≠
Unlimited Usage
```

y:

```text
AI Entitlement
≠
AI Credit Balance
```

---

# 2. Principio central

La aplicación debe utilizar una unidad comercial propia:

```text
AI Credits
```

El usuario no interactúa con:

```text
tokens
input tokens
output tokens
provider pricing
OpenRouter pricing
model pricing
```

Mantener:

```text
Product Credits
≠
Provider Tokens
≠
Provider Cost
```

---

# 3. Access Model

Para ejecutar una capability AI deben cumplirse:

```text
AI enabled
+
authenticated user
+
effective product access allows AI
+
capability entitlement
+
enough credits
+
rate limit available
```

---

# 4. Product Access Integration

Los estados efectivos son:

```text
TRIAL

PRO

EXPIRED_READ_ONLY
```

Reglas:

```text
TRIAL
→ AI allowed within trial credit allowance

PRO
→ AI allowed within billing-period allowance

EXPIRED_READ_ONLY
→ AI disabled
```

---

# 5. Trial AI Model

El trial recibe:

```text
50 AI credits total
```

durante todo el trial.

No:

```text
50 credits / month
```

No:

```text
50 credits every 14 days
```

Es un grant único.

---

# 6. Trial Grant

Al iniciar el trial:

```text
Trial Started
↓
Create one TRIAL_INITIAL_GRANT
↓
50 credits
```

Unique conceptual:

```text
userId
+
TRIAL_INITIAL_GRANT
```

Esto evita grants duplicados por retries.

---

# 7. Trial Credits Expiration

Los créditos de trial:

```text
expire at trial_ends_at
```

aunque no hayan sido consumidos.

Ejemplo:

```text
Trial ends

23 credits remain
↓
those credits are no longer usable
```

---

# 8. Trial Credits Do Not Roll Into Pro

Si usuario activa Pro:

```text
remaining trial credits
≠
purchased credits
```

Recomendación inicial:

```text
trial allowance expires
+
Pro billing-period allowance starts
```

No sumar automáticamente:

```text
remaining trial
+
300 Pro
```

para evitar inconsistencias comerciales.

---

# 9. Pro AI Model

PRO recibe:

```text
300 AI credits
per effective billing period
```

El período debe estar asociado al billing real:

```text
current_period_start

current_period_end
```

---

# 10. Pro Grant

Cuando un período Pro se confirma:

```text
userId
```

---

# 11. Renewal

Cada nuevo período efectivo:

```text
New billing period
↓
new 300-credit grant
```

El webhook puede llegar repetido.

Eso no puede duplicar el grant.

---

# 12. Expired Read-Only

Cuando:

```text
EffectiveProductAccess
=
EXPIRED_READ_ONLY
```

AI debe estar:

```text
disabled
```

Incluso si existe saldo histórico no expirado por un bug/read model antiguo.

El access state prevalece.

---

# 13. Purchased Credits

Post-MVP se pueden vender:

```text
Purchased AI Credits
```

Características recomendadas:

```text
do not expire with normal billing period

do not disappear on downgrade

remain separate from trial/monthly grants
```

# 14. Purchased Credits And Expired State

Decisión recomendada inicial:

aunque un usuario tenga purchased credits:

```text
EXPIRED_READ_ONLY
→ cannot use AI
```

porque AI forma parte del producto activo.

Los créditos comprados se conservan para futura reactivación.

# 158. Final Product Rule

La IA debe estar suficientemente disponible durante el trial para demostrar valor, pero suficientemente limitada para mantener el costo de adquisición bajo control.

La suscripción Pro debe ofrecer un allowance útil y predecible, pero nunca exposición ilimitada a costos de proveedor.

La regla final es:

```text
Access
↓
Entitlement
↓
Credits
↓
Execution
↓
Audit
```

Nunca:

```text
Prompt
↓
Unlimited Provider Usage
```
