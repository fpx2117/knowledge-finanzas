# Subscription Plans & Product Limits

## 1. Objetivo

Este documento define el modelo comercial y de acceso del producto.

Reemplaza el enfoque anterior:

```text
FREE
+
PRO
```

por:

```text
TRIAL
+
PRO_MONTHLY
+
EXPIRED_READ_ONLY
```

Este documento define:

* qué estados comerciales puede tener un usuario;
* qué funcionalidades están disponibles en cada estado;
* qué límites de uso aplican;
* cómo funciona el trial;
* qué ocurre cuando el trial expira;
* qué ocurre cuando una suscripción Pro finaliza;
* cómo deben implementarse entitlements y límites;
* qué funcionalidades permanecen accesibles en modo read-only;
* cómo deben protegerse los costos variables de IA y WhatsApp.

Este documento complementa:

```text
docs/10-billing-subscriptions-mercadopago.md
docs/10.2-pricing-unit-economics.md
docs/08-ai-openrouter.md
docs/08.1-ai-credits-and-usage.md
docs/09-notifications-alerts.md
docs/16-billing-mercadopago-slice.md
```

Principio central:

```text
Commercial State
≠
Billing Provider State
≠
Entitlement
≠
Usage Limit
```

---

# 2. Modelo comercial inicial

El producto tendrá inicialmente un único plan pago:

```text
PRO_MONTHLY
```

y un período de prueba inicial:

```text
TRIAL
```

Cuando el usuario no tiene un trial activo ni una suscripción Pro activa:

```text
EXPIRED_READ_ONLY
```

No existe un plan FREE permanente en la primera versión comercial.

---

# 3. Estados efectivos del producto

Definir:

```text
TRIAL
PRO
EXPIRED_READ_ONLY
```

Opcional futuro:

```text
PRO_YEARLY
```

pero no forma parte del lanzamiento inicial.

---

# 4. Flujo principal

```text
NEW USER
   ↓
TRIAL
14 days
   ↓
   ├── subscription becomes active
   │           ↓
   │          PRO
   │
   └── trial expires
               ↓
       EXPIRED_READ_ONLY
```

Si un usuario Pro cancela o su suscripción termina:

```text
PRO
 ↓
subscription no longer effective
 ↓
EXPIRED_READ_ONLY
```

---

# 5. Filosofía comercial

El producto no debe utilizar restricciones artificiales para generar frustración.

El trial existe para demostrar el valor completo del sistema.

Durante el trial el usuario debe poder experimentar el loop principal:

```text
Create accounts
↓
Record transactions
↓
Track debts
↓
Plan obligations
↓
Use budgets
↓
Understand cashflow
↓
Experience AI assistance
↓
Receive useful notifications
```

Al terminar el trial:

```text
data remains accessible
```

pero nuevas operaciones de gestión financiera quedan bloqueadas hasta activar Pro.

# 7. Trial Start

El trial comienza cuando el usuario completa la creación inicial de su cuenta.

Guardar:

```text
trial_started_at
trial_ends_at
```

El valor:

```text
trial_ends_at
```

debe persistirse.

No recalcularlo dinámicamente como:

```text
createdAt + 14 days
```

en cada request.

Esto permite:

```text
extensions
support adjustments
future experiments
```

# 27. EXPIRED_READ_ONLY

Cuando el usuario no tiene:

```text
active trial
```

ni:

```text
effective Pro subscription
```

su estado se convierte en:

```text
EXPIRED_READ_ONLY
```

Este estado no debe eliminar datos.

---

# 28. Read-Only Philosophy

Principio:

```text
Expired
≠
Locked Out Of Own Data
```

El usuario conserva acceso a su información histórica.

---

# 29. EXPIRED_READ_ONLY Can Do

Debe poder:

```text
sign in

view dashboard history

view accounts

view account balances

view transactions

view debts

view debt installments

view past debt payments

view budgets

view scheduled items

view recurring rules

view historical reports

view existing notifications

view billing settings

export personal data

upgrade to Pro

delete account
```

---

# 30. EXPIRED_READ_ONLY Cannot Do

No puede:

```text
create transactions

edit financial transactions

create accounts

create transfers

create debts

record debt payments

create budgets

create scheduled transactions

create recurring transactions

post scheduled transactions

use AI

run AI scenarios

prepare AI actions

receive premium WhatsApp alerts

create new financial configurations
```

# 43. Trial Expiration

No depender de que corra un worker exactamente en el segundo de expiración.

```text

cleanup

```

pero no son la única fuente de verdad.

```text
SIGN UP
   ↓
14-DAY TRIAL
   ↓
   ├── sees value
   │      ↓
   │   PRO — USD 7.99/month
   │
   └── does not subscribe
             ↓

             ↓
      data remains available
             ↓
      user can activate Pro later
```

El objetivo comercial no es encerrar al usuario.

El objetivo es permitirle experimentar suficiente valor durante el trial para que continuar usando el producto activamente justifique la suscripción.

El acceso histórico y la portabilidad de datos se mantienen incluso cuando la suscripción no está activa.
