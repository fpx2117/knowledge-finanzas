# Referrals & Affiliates

## 1. Objetivo

Este documento define el sistema de referidos y afiliados de la plataforma.

El sistema debe permitir:

```text
existing user
or
external affiliate
↓
shares referral link/code
↓
new user registers
↓
attribution recorded
↓
new user activates / subscribes
↓
reward becomes eligible
↓
reward granted
```

Principio central:

```text
Referral
≠
Promotion Code
≠
Affiliate Payout
≠
Paid Subscription
```

---

# 2. Casos de uso

El sistema debe soportar inicialmente:

```text
user referrals

influencer referrals

partner campaigns

affiliate links

launch campaigns
```

Ejemplos:

```text
Invitá a un amigo.
Si se convierte en Pro,
obtené 30 días de Pro.
```

O:

```text
Creator referral

10 paid conversions
→ reward / commission
```

---

# 3. Referral vs Promotion

Una promoción funciona así:

```text
PROMO CODE
↓
direct benefit
```

Un referral funciona así:

```text
REFERRER
↓
REFERRED USER
↓
required event
↓
reward
```

Por lo tanto:

```text
Referral Code
≠
Promotion Code
```

---

# 4. Referral vs Affiliate

Separar:

```text
REFERRAL
```

de:

```text
AFFILIATE
```

Referral:

```text
normal product user
invites another user
```

Affiliate:

```text
creator
partner
publisher
influencer
organization
```

que puede generar múltiples conversiones.

---

# 5. MVP Strategy

Para V1 implementar primero:

```text
USER REFERRALS
```

Preparar arquitectura para:

```text
AFFILIATES
```

sin implementar inicialmente pagos monetarios automáticos.

---

# 6. Recommended Initial Referral Offer

Ejemplo recomendado:

```text
Invite a friend

Friend becomes paying Pro
↓
Referrer receives
30 days promotional Pro access
```

El usuario referido puede recibir opcionalmente:

```text
extra trial days
```

o:

```text
promotional benefit
```

pero no es obligatorio inicialmente.

---

# 7. Reward Philosophy

La recompensa debe ocurrir después de una acción de valor real.

Preferir:

```text
referred user becomes paid Pro
```

No:

```text
referred user creates account
```

Esto reduce abuso.

---

# 8. Conversion Event

Evento inicial recomendado:

```text
FIRST_PAID_PRO_ACTIVATION
```

Una cuenta referida se considera convertida cuando su primera suscripción Pro efectiva se confirma.


```text

```

---

# 20. Attribution Freezes At Signup

```text

```

# 23. Referral Abuse


# 24. Referral Qualification



# 25. Reward Delay

no entregar recompensa monetaria instantánea.

Para acceso Pro promocional se puede otorgar inmediatamente después de confirmación real de Pro.

Para afiliados monetarios futuros:

usar período de hold.

# 35. Reward While Referrer Is Paid Pro


---

# 36. Recommended Paid Subscriber Reward


```text

Referral reward failure cannot roll back paid billing.
```

# 186. Final Product Rule

El referral program debe premiar adquisición real y no simples registros.

La regla inicial es:

```text
SHARE
↓
SIGNUP
↓
TRIAL
↓
PAID PRO
↓
REWARD
```

No:

```text
SHARE
↓
SIGNUP
↓
FREE REWARD
```

Esto reduce abuso, mantiene los unit economics controlados y conecta la recompensa directamente con ingresos reales del producto.
